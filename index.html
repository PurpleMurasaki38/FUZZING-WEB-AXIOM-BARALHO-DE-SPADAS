Guia de Fuzzing Web com FFUF + HexStrike

Descoberta de diretórios e páginas em painéis e servidores web da empresa

O que este teste faz

O ffuf (Fuzz Faster U Fool) testa milhares de caminhos em um servidor web usando uma lista de palavras (wordlist) e registra quais responderam. Serve para mapear painéis de administração, páginas esquecidas, backups expostos e arquivos sensíveis em sua própria infraestrutura (roteadores, APs, servidores internos, portais da empresa).

Regra da empresa: rode este teste apenas em equipamentos e domínios pertencentes à empresa ou com autorização formal por escrito. Nunca contra redes de terceiros, clientes ou sites externos.

1 Pré-requisitos

No Kali Linux, confirme que o HexStrike está no ar:

curl -sS http://127.0.0.1:8888/health

Resposta esperada: um JSON com status healthy. Se não responder, inicie o servidor:

cd ~/cerebrocaine/hexstrike-ai
source ../.venv/bin/activate
python3 hexstrike_server.py

2 O comando principal

Substitua SEU_ALVO pelo IP ou domínio do equipamento a testar (ex.: 192.168.1.1:8080). Execute no terminal:

PAYLOAD='{
  "url": "http://SEU_ALVO/FUZZ",
  "wordlist": "/usr/share/wordlists/dirb/common.txt",
  "mode": "directory",
  "match_codes": "200,204,301,302,307,401,403,405",
  "additional_args": "-ac -e .php,.html,.txt,.bak,.zip -t 40 -rate 100 -timeout 10 -of html -o /tmp/resultado.html"
}'

curl -sS -X POST http://127.0.0.1:8888/api/tools/ffuf \
  -H "Content-Type: application/json" \
  -d "$PAYLOAD" | jq '{success, stdout, stderr, exit_code}'

# 3) Relatório
ls -lh /tmp/resultado.html && firefox /tmp/resultado.html

O que significa cada parâmetro

ParâmetroFunção
urlAlvo do teste. A palavra FUZZ é substituída por cada palavra da lista.
wordlistLista de caminhos testados (~4.600 entradas no common.txt do Kali).
modedirectory = fuzzing de caminhos/pastas.
match_codesSó registra respostas com esses códigos HTTP (páginas reais, redirects, pedidos de login).
-acAuto-calibração: descarta respostas genéricas (falsos "404" que na verdade existem).
-e .php,...Testa cada palavra também com essas extensões.
-t 40 -rate 10040 threads, no máximo 100 requisições/segundo.
-timeout 10Desiste de uma resposta após 10 segundos.
-of html -o ...Gera o relatório em HTML em /tmp/resultado.html.

3 Acessar o resultado

O relatório fica em /tmp/resultado.html na máquina onde o HexStrike roda.

# Com interface gráfica:
firefox /tmp/resultado.html

# Via SSH (sem interface): sirva por HTTP e acesse do seu navegador
cd /tmp && python3 -m http.server 8090
# Depois abra: http://IP_DO_KALI:8090/resultado.html
Arquivo não apareceu? O resultado também vem no campo stdout da resposta da API. Verifique com find / -name 'resultado*.html' 2>/dev/null. Se o HexStrike rodar em Docker, copie com docker cp <container>:/tmp/resultado.html .

4 Ajustes por cenário

CenárioAjuste no additional_args
Roteador/AP (hardware sensível)-t 10 -rate 20 — reduz agressividade para não travar o equipamento
Painel com login-H "Cookie: SESSAO=valor" — sessão copiada do navegador logado
HTTPS com certificado próprio-k e troque http:// por https:// no campo url
Quer dados filtráveis (JSON)-of json -o /tmp/resultado.json
Dica: gerar -of json além do HTML permite filtrar os achados depois: jq -r '.results[] | "\(.status) \(.url)"' /tmp/resultado.json

5 Interpretação dos códigos no relatório

CódigoSignificadoAção
200Página existe e é públicaVerificar se deveria estar exposta
301/302/307RedirecionamentoSeguir o destino manualmente
401/403Existe, mas pede autenticaçãoInteressante: painel admin, API, backup
405Método não permitidoIndica endpoint real — investigar
